Note the project venv is `backend/.venv` and has no pytest — unittest is the runner here. `alembic heads`

programmatically, not by eye. No frontend changes, so no `tsc` run and no `/qa`.

Three real bugs were found and fixed during the run, not just failing assertions:

1. **Replay ordering depended on random UUIDs.** The tiebreak for events sharing an instant was `str(id)`,
   so two users taking the same actions in the same order could score differently depending on UUID luck.
   Now ordered by `(occurred_at, created_at, id)` — insertion order, and stable across replays.
2. **Pruning erased `last_event_at`.** Only raw events know the true instant, so a rebuild after pruning
   reset it to null. It is now preserved when replay has nothing newer to offer.
3. **A crowded day silently burned a once-ever award.** The derived idempotency key for once-per-subject
   events was lifetime-scoped, so an award blocked by the 60-point daily cap could never be earned again —
   the ledger refused the later attempt. Cap-subject once-ever keys are now day-scoped; the once-ever
   *award* is still enforced during replay. Cap-exempt milestones keep their lifetime key, so onboarding
   stays exactly `onboarding_handled:v{flow_version}` as D-121 specifies.

Also hardened: concurrent first events for a new user would both insert a summary row and one would 500.

## Judgment calls worth knowing about

- **`meaningful_return_day` is derived during replay, not recorded by callers.** It is a property of the
  day's own qualifying activity, so deriving it means it cannot be emitted spuriously or missed. Same
  points either way.
- **No partial awards under the daily cap.** An event that does not fit in the remaining budget does not
  award and does not consume its once-ever key, so the action earns full value on a later day. Partial
  credit would burn a once-per-subject award for a fraction of its worth.
- **`occurred_at` is not accepted from clients** — server clock only. A client-supplied instant would let
  a caller backdate across the Asia/Kolkata boundary and mint a fresh 60-point cap.
- **`lifetime_points` is not exposed by the API.** It can sit below the displayed high-water mark after a
  retune, and showing both would surface exactly the decrease the floor exists to hide.
