# 26-Aug-2026 — BQ-116 account-entry interactive fixture prototype

## What changed

Built the BQ-116 standalone, fixture-only interactive prototype of the account-entry journey — the artefact
BQ-117 owner validation will walk. New folder `docs/features/account-entry/prototype/`:

- `index.html` + `styles.css` + `app.js` — plain HTML/CSS/vanilla JS, matching the arya/baseline prototype
  convention (`docs/features/<slug>/prototype/`). No build step, no framework, no network, no FastAPI, no
  Supabase, no `localStorage` — all state is in-memory and resets per task.
- Left task panel: the twelve `ACCEPTANCE_MATRIX.md` Section-E scenarios (register-new, sign-in,
  restart-resume, wrong-password vs. unknown-email, duplicate registration, unconfirmed-email, expired
  session, offline, permission-denied, logout, account switch, not-configured) + a 4-check record mapping to
  Section E (comprehension / neutrality / recovery / no-residue).
- Right device stage: the account-entry app as an in-memory state machine (not-configured, loading/restore,
  login, register, submitting, confirm/unconfirmed, home, expired, permission-denied) plus a clearly-labelled
  **Fixture controls** strip that injects mid-session events a static prototype can't self-trigger (relaunch,
  expire, drop/restore connection, deny a request, toggle config).
- Reuses the existing IBM Plex Sans / Newsreader / IBM Plex Mono font faces and warm-ledger design tokens
  verbatim from the arya prototype (accept criterion (b)).

Realizes the three owner-ruled decisions:
- **D-153** — expired-session and offline surface a **non-blocking banner + manual retry**; the expired
  subject's data is cleared behind the banner (no stale-authenticated illusion); no forced immediate logout,
  no silent re-auth; offline preserves the user's place and never resends silently.
- **D-154** — enumeration-safe copy: `resolveLogin` collapses unknown-email and wrong-password into **one
  identical branch** (identical message constant, identical field flagging); registration never branches on
  whether the email exists, so a new and an already-registered email produce the **identical** handoff. A
  load-time console self-check asserts the two login causes are indistinguishable.
- **D-155** — logout and account-switch **actively clear** device-local state immediately (not at next load),
  and a simulated late in-flight response from the prior account is discarded and shown as discarded in the
  fixture log — no residue window.

`README.md` gained a run/how-to section (serve the repo root with `python3 -m http.server`, open the
prototype path), the fixture-account table, and a BQ-117 walkthrough mapping to Section E's four checks.

`app/` and `backend/` were **not** modified. No schema, no new library, no money/legal/principle change.
