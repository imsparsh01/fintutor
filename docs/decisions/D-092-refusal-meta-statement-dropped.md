# D-092 — The refusal-before-result meta-statement is dropped; the parallel structure carries neutrality on its own

- **Tier:** 3 — owner-decided directly in conversation. Trigger 2 (advice-line messaging) and trigger 3
  (interprets P2, a Compliance-category principle — Tier 3 only).
- **Date:** 10-Aug-2026

## Decision

The mockups draw the comparison flow (Flow 05.1) opening with an explicit refusal, stated before any
numbers appear: *"Before the numbers: I'm not going to tell you which one to do. What I can do is show
both paths in the same detail, and give you the one rate that decides it — so the call is yours with the
maths already done."*

**This meta-statement is dropped.** The comparison flow proceeds directly to the setup and the result.

## What is explicitly retained

Everything structural that the mockups use to *enact* neutrality, unchanged:

- Identical parallel columns — same field order, same weight, same styling, no hero path and no
  "recommended" chip.
- The **order note** ("ORDER = AS ENTERED"), stating that sequence is input order and not preference.
- The deciding figure ("THE NUMBER TO WATCH", 14.0%) given the largest type on the screen.
- The **"what would make each one true for you"** closing block, handing judgement back with its criteria
  attached.
- The **unnamed third path** stated explicitly ("Neither — if you'd rather hold the ₹50,000 as a buffer.
  That's a real option and it doesn't show up in either column"), so two columns are not read as an
  exhaustive choice set.

Only the narration of the refusal is removed. Nothing that produces the neutrality is touched.

## Why

The mockups' own argument for the meta-statement was that a refusal stated *afterwards* reads as a dodge,
while stated *upfront* it reads as the terms of the exercise. The owner's judgement is that on this
surface the structure already communicates it: the user is looking at two identically-weighted columns, an
order disclaimer, and a named third option. Narrating "I'm not going to tell you which one to do" over the
top of a screen that visibly is not telling them adds a sentence about the app's posture in the exact
moment the user came for arithmetic.

There is a real risk in the retained version, on the record: pre-announcing a refusal draws attention to
the refusal as the notable event, rather than to the mechanism and the breakeven the product wants to be
judged on. Confidence spent on the maths reads as rigour; confidence spent on explaining the silence reads
as anxiety about it.

## Why this is consistent with D-091, not in tension with it

The two decisions were made in the same conversation and point in opposite directions, deliberately:

- **D-091's block applies where the user is looking at their own figure** — a holding, their 80C room,
  their ESOP cost — and a verdict is the natural next thought that *nothing on screen addresses*. The
  interface is otherwise silent, so the boundary is invisible unless stated.
- **D-092's case is a screen whose entire structure is the neutrality.** Two parallel columns, an order
  note, and a named third option are the statement. A sentence restating it is redundant with what the
  user can already see.

The extracted test, reusable for future surfaces: **state the refusal where the neutrality is otherwise
invisible; let the structure speak where it is already visible.**

## Reversibility

High — removing a copy block. As with D-091, note that re-adding it is a Tier-3 decision, not a Tier-1
copy edit, because it is advice-line messaging.
